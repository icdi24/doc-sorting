# 中文课程报告 / 实验报告排版规范

用于给 `docx_format.py` 的规则文件定参。半磅值 = 磅值 × 2（Word 的 `w:sz`）。

## 字号对照

| 中文号 | 磅值 pt | `w:sz` 半磅 | 典型用途 |
|---|---|---|---|
| 小六 | 7.5 | 15 | 脚注、超密表格 |
| 小五 | 9 | 18 | **图注 / 表注** |
| 五号 | 10.5 | 21 | **正文**、题干 |
| 小四 | 12 | 24 | **小节标签** |
| 四号 | 14 | 28 | 二级标题 |
| 小三 | 15 | 30 | — |
| 三号 | 16 | 32 | 一级标题 |

## 常用排版规格

| 元素 | 字号 | 加粗 | 对齐 | 缩进 | 说明 |
|---|---|---|---|---|---|
| 图注 | 9pt (18) | 否 | 居中 | 无 | 紧跟图片下方，`图 X-Y 说明` |
| 表注 | 9pt (18) | 是 | 居中 | 无 | 置于表格上方，`表 X-Y 说明` |
| 标签行 | 12pt (24) | 是 | 继承 | 无 | `程序截图：`/`运行结果：`/`文字说明：` |
| 正文段 | 10.5pt (21) | 否 | 两端对齐 | 首行 2 字符 | 与题干一致 |
| 题干 | 继承模板 | 否 | 继承 | 无 | 不要改动模板原文 |

## 首行缩进

Word 的「首行缩进 2 字符」需要**同时**写两个属性：

```xml
<w:ind w:firstLine="420" w:firstLineChars="200"/>
```

* `firstLineChars="200"` = 2 字符（×100）
* `firstLine` 是回退值（twips），`firstLine = 20 × 字符数 × 字号pt`
  —— 10.5pt 正文即 `20 × 2 × 10.5 = 420`

只写 `firstLineChars` 会在部分渲染器（含 WPS、LibreOffice）下退化为 0 缩进，
这也是编辑器 SDK `first_line_indent_chars` 的产物特征（见 `pitfalls.md`）。

## 图注命名

按截图**实际内容**命名，不要写「图 1-1 截图」这类无信息量的文字。

* 编号：`图 {部分号}-{序号}`，如 `图 3-14`；表用 `表 2-1`
* 正文：源码截图写「XX 类的代码」「XX 方法的实现」；
  运行截图写「XX 的运行结果」；结构图写「XX 的类图 / 继承关系」
* 示例：
  * `图 1-2 子类 MenSingle 的代码`
  * `图 2-6 AdminOffice 类与 ExperimentCenter 类的代码`
  * `图 3-23 泛型信息管理类 InformationManager 的运行结果`

## 补写正文的语气

补空白文字时要像**该课程的学生本人**写的，而不是文档生成器：

* 先写思路，再写关键 API / 数据结构，最后写运行结果说明了什么
* 用第一人称受教视角：「本次实验通过……掌握了……」
* 避免：绝对化结论、营销腔、大段背诵式定义
* 每段 3~6 句，正文段之间空行 + 首行缩进
* 引用题目里已有的类名 / 方法名，保持术语一致

## 常见排版缺陷对照

| 现象 | 根因 | 处理 |
|---|---|---|
| 表格第一列内容换行 | 单元格段落被误加首行缩进 | `clear_indent` |
| 题干文字突然变大加粗 | run 被误套 `size_pt`/`bold` | 撤销，仅对标签行生效 |
| 图注与图片分页断裂 | 图注段缺少「与下段同页」 | 保持图注紧跟图片段 |
| 中文引号变成直引号 | 补写内容时用了 ASCII 引号 | 正文用 `“”`「」，配置里用 ASCII |
